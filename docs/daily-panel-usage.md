# Codex Usage · 独立今日统计面板

运行 `CodexDaily.exe` 后只显示 Windows 托盘图标，不占用任务栏。点击蓝色柱状图图标，在图标所在屏幕的工作区边缘弹出统计面板；再次点击图标、点击外部、按 Esc 或点击关闭会收起。图标若被系统折叠，在任务栏的“^”隐藏图标区域查找。右下角电源按钮或托盘右键“退出”可彻底结束。

窗口底部支持复制统计、立即刷新、打开日志目录、退出。每 10 秒自动刷新，面板收起后也继续更新；首次读取积压时每秒继续读取。托盘悬停提示只显示“今日总 token · 估算平均 TPS”（数值带 ≈），输出明细保留在面板中。Windows 通知区没有截图中 macOS 菜单栏的常驻文字，数值显示在面板和托盘提示中。

托盘菜单“暂停自动刷新”只停止新的自动刷新触发，不暂停 Codex，也不取消已经进行的读取。暂停时手动刷新仍可用；取消暂停会立即请求刷新。

## 统计范围

- 本机时区的今日请求，来自选定 home 下的 `sessions` 和 `archived_sessions`。路径按显式 `--codex-home <目录>`、非空白的 `CODEX_HOME`、用户目录的 `.codex` 的顺序确定。
- 只汇总根会话，不计子代理、云任务、其他机器以及服务端未落入本机日志的用量。并非账号全部 token 账单。
- 初次枚举选择当天更新的日志文件，包括保存在旧日期目录中、今天继续使用的会话。最多 32 个文件，每文件最多 25000 个统计事件，全部来源合计最多 50000 个事件。单次 monitor 刷新的读取预算为 64 MiB；reader 单次批次和普通解析单行的上限分别为 4 MiB，不能把这些限制混为单文件大小上限。选中文件中会保留有界的历史统计以对账修订和午夜生命周期；触及限制、文件不可读或统计格式异常时显示 Partial。
- 超过 4 MiB 的 `response_item` / `turn_context` 普通消息行和 `compacted` 上下文压缩记录，会在持续校验完整 JSON、UTF-8、唯一根类型及结构后丢弃正文，不因此误报 token 统计不完整。工具调用与返回的允许时序字段会以有界流式方式提取，即使字段位于大段正文之后也可读取；无法识别的超大工具时序会让相应来源的估算 TPS 不可用。超大的统计行、未知根类型、歧义或损坏行仍标记 Partial，不能静默漏算。
- 只投影统计字段到内存；不保存聊天正文、不读取认证文件、不发起账号查询。日志以只读共享方式打开。统计不会写回 Codex。
- 历史分类、首现、闭合及冲突依据只保留在当前 monitor 实例内。重启后的新实例无法证明启动前已丢失来源的完整性；头部/读取边界探针也不保证发现任意内部改写。证据容量不足或未知尾部可能使统计继续保守地标记 Partial。

## 数值含义

**Total input/output** 为今日按请求身份去重的输入和输出。每个请求按最早有效发生时间归入日期，最后有效修订替换 token 数值；午夜之后收到的修订不会变成另一天的新请求。缓存是输入的一部分，推理是输出的一部分；两者不能再次加到总量中。旧格式 token_count 累计快照不相加；仅有旧格式时不编造今日总量。缺失数值显示 `—`。

已知为零的统计仍显示 `0`；`No data` 不是零用量的证明。缺失依据仍影响当前统计时保留 Partial；依据恢复或不再影响当前统计后解除对应提示。其他缺失或冲突仍可使整体保持 Partial，恢复冲突记录不自动恢复时长/TPS 资格。`Partial=false` 不代表完整账号账单。

同一天混合出现现代请求和旧格式快照时，若无法证明快照已被现代请求覆盖，保留已确认的现代请求小计，并提示“统计不完整：旧格式快照覆盖关系未知，无法还原全部今日用量”。其他会话或回合存在现代请求，不能消除这项提示；已完整对账的镜像快照不会重复累计或触发这项告警。覆盖规则与合成验收记录见[统计完整性验证](statistics-integrity-validation.md)。

**Total tokens / 今日总 token** 为输入与输出相加，在面板、托盘提示和复制统计中同时提供。缓存和推理不再另加。输入或输出未知、无效或总和超出整数范围时保持未知；统计不完整时托盘总量带“部分”提示。

**Average speed · est. / TPS** 使用当天合格完成回合的输出 token，除以同一组回合扣除首字延迟和可识别工具等待后的净处理秒数。首字延迟直接读取完成记录的 `time_to_first_token_ms`；工具等待以调用与返回记录的时间戳配对估算。每个回合将首字等待与工具等待区间先求并集，重叠或并行工具等待只扣一次；不同回合分别累计。

这仍是日志估算平均速度：TTFT 是整轮首 token 延迟，未必等同界面的可见首字，也不能还原工具返回后每次模型请求的首字等待；剩余时间仍可能包含推理、网络和调度。它不是实时或纯解码 TPS。运行中、缺少可靠时长或 TTFT、工具配对不完整/有冲突/归属不明、对账不完整、跨日以及净时间不为正的回合不计入；不会退回旧口径或把缺失等待视为零。面板下方显示 TPS 纳入与排除的完成回合数，悬停可查看已扣等待时长。因此当日总输出不一定等于 TPS × Net processing time。

开始/结束事件与声明耗时相差超过 1 秒或声明耗时的 5%（取较大值）时，该回合不计速度。回合结束后收到的有效修订，仍按原始发生时间定位；只有最终 token 和回合快照能重新对账时才保留该回合 TPS。缺少真实回合内发生证据时，不臆造开始时间。

同一实例已观察到的唯一历史 start 即使暂时不在当前可读来源中，仍约束同 session/turn 的声明耗时资格。它只用于拒绝矛盾回合，不用于补出活动区间、TTFT、处理时长或 token。合法 token 小计和时长/TPS 的可用性分别判断。该路径的原始失败与修复回归见[PR #1 最终验证记录](pr1-final-validation.md)。

**Net processing time** 为纳入估算 TPS 的同一组回合扣除首字和工具等待区间并集后的时长之和。**Active time** 为裁剪到本地当日和当前时刻后的有效回合区间并集，重叠并发时间只计算一次，仍包含首字与工具等待。只有近期、该 root 最新且未被已知闭合或后继事实排除的开始事件，才可在 15 分钟观察资格内暂计至当前；超时后停止贡献该未闭合区间，没有其他有效区间时显示 `—`。这不是服务端仍在执行或人工工作时长的证明，历史摘要也不补出缺失活动区间。

**Weekly allowance** 仅使用本机日志中有效的 10080 分钟窗口，显示剩余百分比 `100 − usedPercent`、采样时间和重置时间。有重置时间的快照到期失效；没有重置时间时仅接受最近 15 分钟的快照。它是历史快照，账号后续使用可能尚未写入。没有有效周窗口时显示 No data；不能由 token 数推算。多额度桶出现歧义时不选择一个冒充整个账号。

## 演示和开发

| 参数 | 行为 |
| --- | --- |
| `--codex-home <目录>` | 显式选择日志 home；验收使用仅含合成日志的新物理目录 |
| `--demo` | 固定演示数字，不读取真实日志 |
| `--render <PNG路径>` | 隐含 demo，渲染演示面板后退出 |
| `--snapshot <JSON路径>` | 导出一次数字快照后退出；与 demo 组合时导出演示值 |

render 与 snapshot 不能同时使用；未知选项，或需要路径值的选项位于命令末尾且没有下一参数时，返回 2，未实现 `--help`。snapshot 最多在首次读取后继续补读 64 轮，仍有积压时返回 3，否则正常导出返回 0；返回 0 不要求 `IsPartial=false`，也不能代替普通 EXE 界面验收。输出路径的父目录必须已存在，已有文件可能被覆盖，请使用新路径。部分执行异常会进入返回 1 的处理路径：snapshot 尝试写入异常类型，普通模式显示错误提示；不保证所有异常都产生输出文件或返回统一退出码。

普通 EXE 隔离验收应显式使用 `--codex-home <合成目录>`，且不带 demo/render/snapshot。确认该目录、其子目录及所有祖先路径均未通过目录联接或符号链接重定向到真实 home；显式目录参数不是操作系统沙箱。

执行任何 dotnet 或构建脚本前，设置 `$env:DOTNET_GENERATE_ASPNET_CERTIFICATE = 'false'`。独立构建：`pwsh -NoProfile -File scripts/build-daily-panel.ps1 -OutputDirectory artifacts/<新目录>`。脚本执行核心、读取、格式和弹窗逻辑回归，以及合成数据驱动的 WPF 控件夹具，在相邻的 `.verification` 目录保存证据，然后生成 ZIP。纯逻辑测试、WPF 夹具、辅助 snapshot 与普通 EXE 同实例验收各有覆盖范围，不能互相替代。

历史修复验证阶段，SDK 曾自动生成并安装 ASP.NET Core HTTPS 开发证书。后续禁用自动生成不表示历史证书已撤销或清理，目前没有清理证据；此次审查没有操作证书存储。相关执行记录见[PR #1 最终验证记录](pr1-final-validation.md)。

当前便携版需要 Windows x64 和 .NET 9 Windows Desktop Runtime，其他机器须自行具备对应运行时；本机通过不代表其他环境已验证。没有安装程序、后台服务或开机启动项。卸载时先退出，再删除解压目录。
